<objective>
Migrate CSRF protection from the custom WebMvc CsrfInterceptor to a CsrfValidationFilter running inside the Spring Security filter chain after JWT authentication.

Purpose: The custom CsrfInterceptor runs in the WebMvc interceptor layer, outside the Spring Security filter chain. This creates a gap where Spring Security does not know about CSRF state and the interceptor cannot reliably access the authenticated principal (it depends on SecurityContextHolder being populated by a filter that runs earlier in a different layer). By moving CSRF into a servlet Filter registered in SecurityConfig AFTER JwtAuthenticationFilter, all protection is unified in the security chain and the filter has guaranteed access to the authenticated user via SecurityContext.

Output: New CsrfValidationFilter servlet filter; SecurityConfig with CsrfValidationFilter registered after JwtAuthenticationFilter; WebMvcConfig with CsrfInterceptor registration removed; CsrfInterceptor.java deleted.
</objective>

**(A) Create `backend-spring/src/main/java/com/ulticode/security/csrf/CsrfValidationFilter.java`:**

```java
package com.ulticode.security.csrf;

import com.ulticode.common.exception.BusinessException;
import com.ulticode.common.exception.ErrorCode;
import jakarta.servlet.FilterChain;
import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.security.core.Authentication;
import org.springframework.security.core.context.SecurityContextHolder;
import org.springframework.web.filter.OncePerRequestFilter;

import java.io.IOException;
import java.util.Set;

/**
 * CSRF validation filter that runs within the Spring Security filter chain,
 * after JWT authentication has been established.
 *
 * Replaces the previous CsrfInterceptor (WebMvc interceptor) so that CSRF
 * validation is part of the security filter chain rather than the MVC layer.
 *
 * Validates CSRF tokens on state-changing methods (POST, PUT, DELETE, PATCH)
 * for authenticated users by delegating to the Redis-backed CsrfService.
 */
@Slf4j
@RequiredArgsConstructor
public class CsrfValidationFilter extends OncePerRequestFilter {

    private final CsrfService csrfService;

    private static final Set<String> CSRF_METHODS = Set.of("POST", "PUT", "DELETE", "PATCH");

    @Override
    protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain filterChain)
            throws ServletException, IOException {
        String method = request.getMethod();

        if (!CSRF_METHODS.contains(method)) {
            filterChain.doFilter(request, response);
            return;
        }

        Authentication authentication = SecurityContextHolder.getContext().getAuthentication();
        if (authentication == null || !authentication.isAuthenticated()) {
            filterChain.doFilter(request, response);
            return;
        }

        String userId = authentication.getName();
        if (userId == null || "anonymousUser".equals(userId)) {
            filterChain.doFilter(request, response);
            return;
        }

        String csrfToken = request.getHeader("X-CSRF-Token");
        if (csrfToken == null || csrfToken.isEmpty()) {
            log.warn("CSRF token missing for user {} on {} {}", userId, method, request.getRequestURI());
            throw new BusinessException(ErrorCode.FORBIDDEN, "CSRF token is required");
        }

        String newToken = csrfService.validateAndRotateToken(userId, csrfToken);
        if (newToken == null) {
            log.warn("Invalid CSRF token for user {} on {} {}", userId, method, request.getRequestURI());
            throw new BusinessException(ErrorCode.FORBIDDEN, "Invalid CSRF token");
        }

        response.setHeader("X-New-CSRF-Token", newToken);
        log.debug("CSRF validation and rotation passed for user {} on {} {}", userId, method, request.getRequestURI());
        filterChain.doFilter(request, response);
    }
}
```

Key implementation details:
- Extends `OncePerRequestFilter` so it runs exactly once per request dispatch.
- Skips safe methods (GET, HEAD, OPTIONS, TRACE) -- only validates POST, PUT, DELETE, PATCH.
- Skips unauthenticated users -- `authentication == null`, `!authentication.isAuthenticated()`, or `anonymousUser` all pass through. This means login and register endpoints (which have no JWT yet) are naturally exempt.
- Reads the submitted token from `X-CSRF-Token` request header (matches existing frontend behavior).
- Calls `csrfService.validateAndRotateToken(userId, csrfToken)` which checks Redis and rotates the token.
- Returns the new rotated token in `X-New-CSRF-Token` response header (matches existing frontend behavior).
- Throws `BusinessException(ErrorCode.FORBIDDEN, ...)` on missing or invalid tokens -- the GlobalExceptionHandler handles this consistently.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05 | S (Spoofing) | CsrfValidationFilter | mitigate | CSRF tokens are per-user, stored in Redis with 24h TTL. Token rotation on every validated request prevents replay attacks |
| T-01-06 | T (Tampering) | CsrfValidationFilter | mitigate | Token format is tokenId:tokenValue where both parts are UUIDs. Tampering with either part causes validation failure against Redis store |
| T-01-07 | T (Tampering) | SecurityConfig | mitigate | CSRF filter runs after JWT authentication, ensuring only authenticated users are checked. Anonymous requests skip CSRF validation |
| T-01-08 | I (Information Disclosure) | CsrfService | accept | Token values are UUIDs with no information content. Redis keys include userId but this is internal |
