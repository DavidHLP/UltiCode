<objective>
Replace the broken XssFilter input sanitization with correct XSS prevention via output encoding.

Purpose: The current XssFilter uses regex-based input stripping that corrupts legitimate user content (removing `eval()`, `javascript:`, `<script>` from request parameters, headers, and query strings). This is the wrong layer for XSS defense. XSS must be prevented at the output/rendering layer via encoding, not by stripping at the input layer. OWASP recommends output encoding as the primary defense.

Output: Modified pom.xml with OWASP Encoder dependency; neutered XssFilter that passes content through unmodified.
</objective>

Replace the entire file with:

```java
package com.ulticode.common.filter;

import jakarta.servlet.Filter;
import jakarta.servlet.FilterChain;
import jakarta.servlet.ServletException;
import jakarta.servlet.ServletRequest;
import jakarta.servlet.ServletResponse;
import java.io.IOException;
import org.springframework.core.Ordered;
import org.springframework.core.annotation.Order;
import org.springframework.stereotype.Component;

/**
 * XSS pass-through filter.
 *
 * Previously attempted regex-based input sanitization, which corrupted
 * legitimate user content. XSS prevention is now handled via output encoding
 * with OWASP Encoder at the rendering layer (SEC-06).
 *
 * This filter is retained as a pass-through to preserve its position in the
 * filter chain ordering. It will be removed in a future cleanup.
 */
@Component
@Order(Ordered.HIGHEST_PRECEDENCE + 1)
public class XssFilter implements Filter {

    @Override
    public void doFilter(ServletRequest request, ServletResponse response, FilterChain chain)
            throws IOException, ServletException {
        chain.doFilter(request, response);
    }
}
```

Key changes:
- Remove all Pattern[] definitions (the 6 regex patterns)
- Remove the sanitize() method
- Remove the XssRequestWrapper inner class (which overrode getParameter, getParameterValues, getHeader, getQueryString)
- doFilter() now calls chain.doFilter() directly with no wrapping
- Add javadoc explaining WHY this was changed (SEC-06)
