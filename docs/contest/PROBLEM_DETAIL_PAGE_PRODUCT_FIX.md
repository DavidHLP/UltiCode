# 竞赛题目详情页产品问题与修复文档

> **日期**：2026-06-18
> **状态**：草案 · 待产品/设计/前端评审
> **范围**：`console` 端竞赛详情页的题目列表，以及从题目列表进入后的竞赛题目详情/做题页
> **证据来源**：浏览器页面 `http://localhost:9002/contest/linked-list-special` 标注行「A 反转链表」；代码路径 `console/src/views/contest/detailed/`、`console/src/views/problems/`

---

## 1. 结论摘要

当前页面最大的问题不是视觉主题，而是**比赛业务语境在进入题目后断裂**。

从截图和代码看，竞赛详情页中的题目列表能展示题目 A/B/C、难度、分数、通过率等基础信息；点击后进入的是通用题目页 `/problems/:slug`，通过 `?contestId=...` 临时切换竞赛提交和隐藏题解。这种复用方式降低了开发成本，但从产品和业务角度带来 4 个核心问题：

1. **参赛用户进入题目后失去比赛上下文**：看不到比赛标题、剩余时间、当前分数、排名、罚时、题目 A/B/C 切换、返回比赛等关键竞赛信息。
2. **通用题库行为混入竞赛场景**：顶部仍出现题库、随机题、全站上一题/下一题等入口，容易把用户带出比赛或带到非本场题目。
3. **题目列表的决策信息不足**：行内信息像后台数据表，缺少“我该先做哪题、这题我现在是什么状态、点击后会发生什么”的业务表达。
4. **赛中、赛后、虚拟赛的体验没有分层**：同一套展示没有根据 upcoming/running/finished/virtual 调整主任务，导致比赛转化、完成率、复盘留存都受影响。

建议把当前设计从“题库详情页 + contestId 参数”升级为**竞赛题目工作台**：保留通用题目编辑器能力，但在竞赛模式下提供专属顶部栏、题目导航、实时比赛状态、提交反馈和赛后复盘入口。

## 2. 当前页面现象

### 2.1 竞赛详情页题目列表

从标注截图可见，题目列表行包含：

- 题号：A/B/C
- 标题：反转链表、两数相加、合并 K 个升序链表
- 聚合数据：`0 已解决`、`0 提交记录`
- 难度：简单/中等/困难
- 分数：100
- 通过率：73.2 / 41.2 / 28.4
- 右侧箭头入口

页面上方还有比赛开始时间、时长、参赛人数、是否计分，以及规则说明。题目区在当前 1327x914 视口中位于较靠下位置。

### 2.2 点击题目后的实现方式

代码中 `ContestProblemList.vue` 点击题目后进入：

```ts
{
  name: "problem-detail",
  params: { slug },
  query: contestIsLive.value ? { contestId: props.contestId } : undefined,
}
```

实际承载页面是通用 `ProblemDetailView.vue`。该页面根据 `route.query.contestId` 做两件事：

- 提交时走 `submitContestProblem(contestId, problemId, dto)`
- 在竞赛模式隐藏 Solutions tab，避免赛中泄题

这说明当前所谓“竞赛题目详情页”并不是独立的竞赛题目页面，而是通用题目页的竞赛模式。

## 3. 问题清单与业务影响

### P0-1：竞赛上下文丢失，用户无法做策略决策

**现象**

进入题目后，页面核心区域是题目描述、代码编辑器、测试用例、提交按钮，但缺少比赛中最重要的决策信息：

- 剩余时间
- 当前比赛名称
- 本题编号 A/B/C
- 本题分数、罚时规则
- 我当前总分、已过题数、当前排名
- 本场题目列表与个人状态
- 返回比赛/打开排行榜/查看公告入口

**业务影响**

比赛不是普通刷题。参赛者需要持续判断：

- 这题值不值得继续卡？
- 还有多少时间，是否该换下一题？
- 当前排名是否需要冲刺？
- 这题我是否已经提交过、错了几次、罚时多少？

缺少这些信息会增加用户来回切页、误判策略、放弃比赛的概率，直接影响比赛完成率、提交次数、排行榜浏览和赛后复盘留存。

**修复方向**

在竞赛模式题目页增加 `ContestProblemShell`：

- 顶部左侧：返回比赛、比赛标题、状态徽标
- 顶部中间：剩余时间、当前分数、排名、已过题数
- 顶部右侧：排行榜、公告/Clarification、提交记录
- 题目标题区：`A. 反转链表`、`100 分`、`简单`、`罚时 +300 秒/次`
- 题目切换：A/B/C segmented control，显示个人状态

### P0-2：通用题库导航混入竞赛，可能把用户带出比赛

**现象**

`LayoutHeaderLeft.vue` 在所有题目详情页中展示：

- 题库入口
- 全站上一题/下一题
- 随机题

其中上一题/下一题调用的是全站题目相邻接口 `/problems/{id}/adjacent`，随机题调用 `/problems/random`。这不是竞赛题目集合。

**业务影响**

在比赛中，这些入口会造成明显风险：

- 用户点击上一题/下一题后可能进入非本场比赛题目，但 URL query 仍可能保留 `contestId`。
- 用户点击随机题会直接离开比赛上下文。
- 用户以为自己仍在比赛中，实际提交会失败或进入错误路径。
- 平台的比赛转化漏斗被污染：离场不是用户主动放弃，而是页面把用户带走。

**修复方向**

竞赛模式下替换顶部通用导航：

- “题库”改为“返回比赛”
- “上一题/下一题”改为本场比赛的上一题/下一题
- 隐藏“随机题”
- 若当前题目不属于该 contest，展示明确错误页：“该题不属于本场比赛”，并提供返回比赛按钮

需要新增或复用一个 contest-scoped adjacency 能力：

```http
GET /contest/{contestId}/problems/{problemId}/adjacent
```

返回本场内上一题/下一题，而不是全站顺序。

### P0-3：题目列表缺少行动导向，不能有效推动“开始做题”

**现象**

题目行现在像数据表：

```text
A 反转链表 0 已解决 0 提交记录 简单 100 73.2 >
```

用户可以点击整行，但视觉上没有明确的主按钮或任务状态。

**业务影响**

比赛详情页最关键的转化动作是“进入第一题并提交”。当前页面没有把入口设计成主行动，尤其新用户可能不知道：

- 点击整行可以进入做题
- 这题是否已解决
- 这题是否推荐先做
- 我是否已经尝试过
- 进入后是否会开始计时或提交到比赛

**修复方向**

将题目行从“表格数据”改成“参赛任务列表”：

- 左侧：题号 + 个人状态图标
- 主信息：标题 + 简短标签
- 决策信息：分值、我的尝试次数、通过人数/提交数、通过率
- 右侧主动作：
  - 未开始：`开始`
  - 已尝试未通过：`继续`
  - 已通过：`查看`
  - 比赛未开始：`未解锁`
  - 比赛结束：`复盘`

### P1-1：信息层级不符合比赛优先级

**现象**

当前竞赛详情页先展示信息卡、规则说明、再展示题目列表。对于 running contest，用户最想看到的是：

1. 还能做多久
2. 我要做哪题
3. 我现在排名/分数如何
4. 是否有公告或规则变更

规则说明占据较大首屏空间，题目列表被下推。

**业务影响**

running contest 的首屏应该服务“立即参赛”，而不是服务“阅读详情”。题目列表下沉会降低进入题目的速度，也会让比赛页面显得像信息展示页而不是赛事工作台。

**修复方向**

根据比赛状态重排页面：

| 状态 | 首屏主任务 | 页面排序 |
|------|------------|----------|
| UPCOMING | 报名/提醒/了解规则 | 状态卡 → 报名 CTA → 时间/规则 → 题目锁定提示 |
| RUNNING | 进入题目/看剩余时间/看排名 | 状态栏 → 题目列表 → 我的进度/排名 → 规则折叠 |
| FINISHED | 复盘/看榜/看题解 | 最终榜入口 → 题目复盘列表 → 题解/讨论 |
| VIRTUAL | 开始或继续虚拟赛 | 虚拟倒计时 → 题目列表 → 虚拟榜/复盘 |

### P1-2：数据文案不业务化，容易被理解为“空数据/坏数据”

**现象**

标注行中展示 `0 已解决`、`0 提交记录`，通过率展示为 `73.2`，没有百分号。对刚开始的比赛，所有题都是 0，用户很难判断这是“没人提交”还是“系统没有数据”。

**业务影响**

竞赛数据需要区分“全场统计”和“我的状态”。现在两者混在一行，且缺少单位和解释，会削弱用户信任。

**修复方向**

调整文案：

- `0 已解决` → `全场 0 人通过`
- `0 提交记录` → `全场 0 次提交`
- `73.2` → `73.2%`
- 个人状态独立展示：`未开始` / `已尝试 2 次` / `已通过`
- 比赛刚开始时用弱提示：`暂无全场提交`

### P1-3：隐藏题解是正确的，但缺少解释

**现象**

竞赛模式下 `useProblemLayout.ts` 会隐藏 Solutions tab，避免赛中查看题解。这是正确的安全/公平设计。

**问题**

如果用户熟悉普通题目页，进入比赛后发现“题解”不见了，缺少解释，会以为功能坏了。

**修复方向**

在题目页信息区提供轻量说明：

```text
题解与公开代码已在比赛期间隐藏，比赛结束后开放。
```

Finished 状态下恢复题解入口，并增加“赛后复盘”标签。

### P1-4：提交反馈不够“比赛化”

**现象**

提交按钮走竞赛提交接口，成功后跳到提交记录 tab。但页面没有明确表达：

- 提交是否计入本场比赛
- 当前判题中/排队中状态
- 本次 WA 是否产生罚时
- 本题是否首次 AC
- 提交后当前分数/排名是否变化

**业务影响**

比赛中的反馈要让用户即时知道“这次提交对比赛结果有什么影响”。单纯展示提交状态不足以支持策略决策。

**修复方向**

提交后展示竞赛结果条：

| 状态 | 文案 |
|------|------|
| Judging | `正在判题，本次提交计入比赛` |
| Accepted | `通过 +100 分，当前已过 1/3 题` |
| Wrong Answer | `未通过，可能产生罚时；建议查看样例与本地测试` |
| Contest Ended | `比赛已结束，提交未计入排名` |

并在本题状态、题目切换器、排行榜摘要中同步更新。

### P1-5：缺少公告/Clarification 入口，比赛运营能力弱

**现象**

Contest API 已有 `getAnnouncements(slug)`，但竞赛题目工作区没有显著公告入口。比赛中题面勘误、样例解释、规则调整对公平性非常关键。

**业务影响**

如果公告只在比赛详情页或不明显位置，用户在做题时可能错过重要信息，造成投诉和比赛公信力下降。

**修复方向**

题目页顶部增加公告入口：

- 有未读公告时展示红点或数量
- 公告弹层不打断写代码
- 重要公告可置顶横幅
- 后续支持 Clarification：用户提问、管理员回复、公开/私密可见

### P2-1：赛后学习闭环不足

**现象**

当前竞赛问题页核心是做题与提交。赛后应出现的复盘能力不足：

- 官方题解入口
- 我的错误提交轨迹
- 同题优秀代码
- 题目讨论
- 虚拟重赛/再次练习

**业务影响**

比赛的长期价值来自赛后学习。没有赛后闭环，用户比赛结束后只看一次排名就离开，留存和内容沉淀都会弱。

**修复方向**

Finished 状态下将题目页切换成“复盘模式”：

- 展示我在本题的提交时间线
- 展示首次 AC 时间、错因分类、最终得分
- 开放题解、公开代码、讨论
- 提供“加入错题本/题单”与“重新练习”

## 4. 目标体验

### 4.1 Running contest 的竞赛题目页

用户进入 `A. 反转链表` 后应立刻看到：

```text
返回比赛 | 链表专题赛 · 进行中 | 剩余 01:21:35 | 我的分数 0 | 排名 -- | 公告 1

A. 反转链表        100 分 · 简单 · 罚时 +300 秒/次
[A 未开始] [B 未开始] [C 未开始]

左：题面/提交记录
右上：代码编辑器
右下：测试用例/测试结果

底部或右上主按钮：运行 / 提交到比赛
```

关键原则：

- 用户始终知道自己在某场比赛中
- 用户可以一键回到比赛
- 用户可以在本场题目之间切换
- 用户不会误入随机题/题库题
- 用户提交后立即看到比赛影响

### 4.2 Finished contest 的竞赛题目页

赛后进入题目应变为复盘导向：

```text
返回比赛 | 链表专题赛 · 已结束 | 最终排名 #18 | 得分 200

A. 反转链表        我已通过 · 首次 AC 00:17:42
[题面] [我的提交] [题解] [讨论] [优秀代码]
```

### 4.3 Virtual contest 的竞赛题目页

虚拟赛要明确和真实赛区分：

```text
返回虚拟赛 | 链表专题赛 · 虚拟赛进行中 | 剩余 01:05:10
题解已隐藏，虚拟赛结束后开放
```

## 5. 修复方案

### Phase 1：先止血，防止用户离开比赛上下文

**目标**：竞赛模式下不再出现错误导航，用户能稳定在本场比赛内做题。

**前端改动**

1. `ProblemDetailView.vue` 判断 `contestId` 后进入竞赛模式。
2. `LayoutHeaderLeft.vue` 在竞赛模式下替换：
   - 题库入口 → 返回比赛
   - 全站 prev/next → 本场 prev/next
   - 随机题 → 隐藏
3. 增加题目归属校验：
   - 当前 slug 不属于 contest 时，展示错误态并返回比赛
4. 增加顶部竞赛摘要：
   - contest title/status/timeLeft
   - problemIndex/score/difficulty

**后端/API**

1. 提供 contest-scoped adjacent API，或在 `/contest/{id}/problems` 返回完整排序后前端本地计算。
2. 当前 contest problem summary 需要包含 `problemIndex`、`problemId`、`slug`、`score`、`penaltyPerWrong`。

**验收标准**

- 在竞赛题目页看不到随机题入口。
- 上一题/下一题只在 A/B/C 之间切换。
- 返回按钮回到 `/contest/linked-list-special`。
- 非本场题目不会被当作本场题提交。
- Solutions tab 仍在赛中隐藏。

### Phase 2：把题目列表改成参赛任务列表

**目标**：提高从比赛详情页进入题目并提交的转化。

**前端改动**

1. 题目列表第一屏优先级上移，running 状态下规则默认折叠。
2. 行结构改为：
   - 题号 + 个人状态
   - 标题 + 难度
   - 分数 + 罚时
   - 全场通过/提交
   - 个人尝试次数
   - 主动作按钮
3. 修正文案和单位：
   - `73.2` → `73.2%`
   - `0 已解决` → `全场 0 人通过`
   - `0 提交记录` → `全场 0 次提交`

**验收标准**

- 用户无需 hover 就能识别主操作。
- A/B/C 三题的个人状态清晰可见。
- 通过率有 `%` 单位。
- running 状态下，题目列表在首屏或接近首屏位置。

### Phase 3：竞赛题目工作台

**目标**：在题目页内补全比赛策略信息。

**前端改动**

1. 新增 `ContestProblemShell` 或 `ContestProblemHeader`。
2. 题目页展示：
   - 剩余时间
   - 我的得分
   - 当前排名
   - 已过题数
   - 公告入口
   - 本场题目切换器
3. 提交结果展示比赛影响：
   - 得分变化
   - 是否 AC
   - 是否产生罚时
   - 排名变化

**后端/API**

需要一个轻量 contest session summary：

```ts
interface ContestProblemSessionSummary {
  contestId: string;
  slug: string;
  title: string;
  status: "UPCOMING" | "RUNNING" | "FINISHED" | "VIRTUAL";
  endsAt: string | null;
  timeLeftSeconds: number | null;
  userScore: number;
  userRank: number | null;
  solvedCount: number;
  totalProblems: number;
  unreadAnnouncementCount: number;
}
```

**验收标准**

- 用户在题目页不用返回比赛也能知道剩余时间和当前进度。
- 提交 AC 后，题目切换器和得分摘要更新。
- 有公告时题目页可见。

### Phase 4：赛后复盘与增长闭环

**目标**：让比赛结束后继续产生学习和留存价值。

**前端改动**

1. Finished 状态开放题解、讨论、公开代码。
2. 本题展示我的提交时间线。
3. 提供“重新练习”“加入题单”“开始虚拟赛”入口。

**验收标准**

- 比赛结束后题解 tab 恢复。
- 用户能从最终榜进入某题复盘。
- 用户能看到自己的历史提交路径。

## 6. 数据与埋点需求

### 6.1 漏斗指标

| 指标 | 定义 | 目标 |
|------|------|------|
| 题目入口点击率 | 进入 contest detail 后点击任一题的人数 / contest detail UV | 提升 |
| 首次运行率 | 进入题目页后点击运行的人数 / 题目页 UV | 提升 |
| 首次提交率 | 进入题目页后提交的人数 / 题目页 UV | 提升 |
| 题目页误离开率 | 题目页进入非本场题或随机题的人数 / 题目页 UV | 降低到 0 |
| 比赛完成率 | 至少提交一次或完成虚拟赛的人数 / 报名人数 | 提升 |
| 赛后复盘率 | 比赛结束后查看题解/提交时间线的人数 / 参赛人数 | 提升 |

### 6.2 关键埋点

```text
contest_detail_view
contest_problem_row_click
contest_problem_enter
contest_problem_switch
contest_problem_run
contest_problem_submit
contest_problem_result_received
contest_problem_leave_to_non_contest
contest_announcement_open
contest_post_review_open
```

所有埋点需携带：

- `contestId`
- `problemId`
- `problemIndex`
- `contestStatus`

- `userParticipationStatus`

## 7. 验收清单

### 产品验收

- [ ] 竞赛题目页首屏能看出当前比赛、当前题号、剩余时间。
- [ ] 竞赛题目页有明确返回比赛入口。
- [ ] 竞赛题目页只能在本场题目之间切换。
- [ ] running/virtual 状态下题解隐藏，并给出解释。
- [ ] finished 状态下题解/复盘入口可见。
- [ ] 题目列表能区分“全场数据”和“我的状态”。
- [ ] 题目列表每一行都有明确主动作。

### 技术验收

- [ ] `contestId` query 不会让非本场题目进入竞赛提交路径。
- [ ] 全站 random problem 在竞赛模式不可见。
- [ ] 全站 adjacent problem 在竞赛模式不可用。
- [ ] 竞赛提交仍走 `submitContestProblem`。
- [ ] 普通题目页不受竞赛模式改动影响。
- [ ] 赛中 Solutions tab 仍不可见。

### 设计验收

- [ ] running 状态题目列表优先级高于长规则说明。
- [ ] 通过率展示百分号。
- [ ] 空数据有语义化文案，不只显示 0。
- [ ] 移动端题目列表不横向挤压关键动作。
- [ ] 题目详情页顶部信息不遮挡编辑器和题面。

## 8. 推荐优先级

| 优先级 | 项目 | 原因 |
|--------|------|------|
| P0 | 替换竞赛模式导航，隐藏随机题，contest-scoped prev/next | 防止用户被带出比赛，是最直接的体验和业务风险 |
| P0 | 增加竞赛题目页顶部上下文 | 解决用户不知道自己在哪场比赛、还剩多久的问题 |
| P1 | 重做题目列表信息层级和主动作 | 提升进入题目与提交转化 |
| P1 | 提交结果比赛化反馈 | 提升赛中策略判断和即时成就感 |
| P1 | 公告入口 | 保障比赛公平与运营可控 |
| P2 | 赛后复盘页 | 提升学习闭环和长期留存 |

## 9. 非目标

本修复文档不建议在本轮处理：

- 重写判题系统
- 改动评分算法
- 开放赛中题解
- 引入复杂社交系统
- 重做全站题目详情页视觉体系

核心原则是：**保留通用题目页能力，但竞赛模式必须有独立业务外壳和严格的竞赛导航边界。**
