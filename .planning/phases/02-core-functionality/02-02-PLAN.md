3. REPLACE the `rejudge()` method (currently a TODO stub) with this implementation:
```java
@Override
public RejudgeResult rejudge(String id, boolean notifyUser) {
    Submission submission = submissionMapper.selectById(id);
    if (submission == null) {
        throw new BusinessException(ErrorCode.SUBMISSION_NOT_FOUND);
    }

    RejudgeResult result = new RejudgeResult();
    result.setSubmissionId(id);
    result.setOldStatus(submission.getStatus());

    try {
        // Build rejudge job with LOW priority (D-07, D-14)
        JudgeJob job = JudgeJob.builder()
            .submissionId(id)
            .problemId(submission.getProblemId())
            .userId(submission.getUserId())
            .language(submission.getLanguage())
            .code(submission.getCode())
            .priority(QueueConstants.Priority.LOW)
            .build();

        queueService.enqueueJudgeJob(job);

        // Reset submission status to Pending
        submission.setStatus("Pending");
        submissionMapper.updateById(submission);

        result.setSuccess(true);
        result.setNewStatus("Pending");
        log.info("Rejudge enqueued for submission: {}", id);
    } catch (Exception e) {
        log.error("Failed to enqueue rejudge for submission: {}", id, e);
        result.setSuccess(false);
        result.setError(e.getMessage());
    }

    return result;
}
```

4. REPLACE the `batchRejudge()` method with batch size validation (D-05):
```java
@Override
public BatchRejudgeResponse batchRejudge(List<String> ids, boolean notifyUsers) {
    if (ids.size() > 50) {
        throw new BusinessException(ErrorCode.VALIDATION_FAILED,
            "Batch size exceeds maximum of 50");
    }

    BatchRejudgeResponse response = new BatchRejudgeResponse();
    response.setTotal(ids.size());
    response.setResults(new ArrayList<>());
    response.setSuccessful(0);
    response.setFailed(0);

    for (String id : ids) {
        RejudgeResult result = rejudge(id, notifyUsers);
        response.getResults().add(result);
        if (result.getSuccess()) {
            response.setSuccessful(response.getSuccessful() + 1);
        } else {
            response.setFailed(response.getFailed() + 1);
        }
    }

    return response;
}
```

Note on JudgeJob fields: The `timeLimitMs` and `memoryLimitKb` fields have `@Builder.Default` values (2000 and 262144 respectively). The builder call above intentionally omits them, using the defaults. Per the PATTERNS.md note, the Problem entity has no timeLimit/memoryLimit fields, so defaults are appropriate for rejudge.

Note on QueueService: The existing `QueueServiceImpl.enqueueJudgeJob()` auto-generates id and createdAt if null. It also sets status to PENDING. No need to set these manually.

Note on RQueue priority limitation (RESEARCH.md A3): The current RQueue is FIFO and ignores the priority field during polling. Jobs are enqueued with priority=LOW as a marker. Actual priority-based dispatch requires a future worker enhancement. This is a known gap documented in the RESEARCH.md, not a phase 02 requirement.
