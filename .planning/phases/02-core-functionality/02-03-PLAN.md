    **Step 1: Create `docker/sandbox/seccomp-profile.json`**

    This profile REPLACES Docker's default profile entirely when passed via `--security-opt seccomp=<path>`. Therefore, use `defaultAction: "SCMP_ACT_ALLOW"` to allow all syscalls by default, with explicit blocks only for the dangerous syscalls listed in D-08. CRITICAL: The clone syscall must NOT be unconditionally blocked -- only block when called with namespace flags (see RESEARCH.md Pitfall 4).

    ```json
    {
        "defaultAction": "SCMP_ACT_ALLOW",
        "architectures": ["SCMP_ARCH_X86_64", "SCMP_ARCH_X86_32", "SCMP_ARCH_AARCH64"],
        "syscalls": [
            {
                "names": [
                    "ptrace",
                    "mount",
                    "keyctl",
                    "unshare",
                    "setns"
                ],
                "action": "SCMP_ACT_ERRNO",
                "args": [],
                "comment": "Block dangerous syscalls for code execution sandbox (D-08)"
            },
            {
                "names": ["clone"],
                "action": "SCMP_ACT_ERRNO",
                "args": [
                    {
                        "index": 0,
                        "op": "SCMP_CMP_MASKED_EQ",
                        "value": 2080505856
                    }
                ],
                "comment": "Block clone with namespace flags (CLONE_NEWUSER|CLONE_NEWNS|CLONE_NEWPID|CLONE_NEWNET|CLONE_NEWIPC|CLONE_NEWUTS). Thread creation (unmasked clone) remains allowed for java/node/python."
            }
        ],
        "_comments": {
            "D-21_syscalls": "wait4, times, getrusage -- used by /usr/bin/time for memory tracking. Allowed by SCMP_ACT_ALLOW default.",
            "D-22_syscalls": "openat, write, unlink -- used for stderr temp files (sandbox-stderr-*.log). Allowed by SCMP_ACT_ALLOW default.",
            "D-15_strategy": "SCMP_ACT_ALLOW default with explicit blocks. Does NOT replace Docker's default -- this IS the full profile. Only dangerous syscalls are blocked."
        }
    }
    ```

    NOTE: `defaultAction: "SCMP_ACT_ALLOW"` is used because `--security-opt seccomp=<path>` REPLACES Docker's default profile entirely (it does not merge). Using SCMP_ACT_ERRNO as default would block ALL syscalls not explicitly listed, breaking all language runtimes. With SCMP_ACT_ALLOW, only the named dangerous syscalls are blocked.

    NOTE on D-21: The `/usr/bin/time -v` command (installed in sandbox Dockerfile, used by ALL 5 language runners in buildDockerCommand) requires syscalls `wait4` (to wait for child process), `times` (to get CPU time), and `getrusage` (to get peak RSS). Since defaultAction is SCMP_ACT_ALLOW, these are automatically permitted. No explicit allow rules are needed. The `_comments` section documents this dependency for maintainability.

    NOTE on D-22: The sandbox redirects stderr to temp files via `File.createTempFile("sandbox-stderr-", ".log")` and `pb.redirectError(stderrFile)`. This requires `openat` (to create/open the temp file in /tmp), `write` (to write stderr data), and `unlink` (to delete the temp file in the finally block). Since defaultAction is SCMP_ACT_ALLOW, these are automatically permitted. No explicit allow rules are needed.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user code -> Docker sandbox | Untrusted user-submitted code runs inside isolated container |
| application -> Docker CLI | Trusted (app constructs docker run command) |
| Docker daemon -> kernel | Enforced by kernel (seccomp, capabilities, namespaces) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-11 | E (Elevation) | ptrace syscall | mitigate | Blocked by seccomp profile (SCMP_ACT_ERRNO) |
| T-02-12 | E (Elevation) | mount syscall | mitigate | Blocked by seccomp profile + --cap-drop ALL removes CAP_SYS_ADMIN |
| T-02-13 | E (Elevation) | keyctl syscall | mitigate | Blocked by seccomp profile |
| T-02-14 | E (Elevation) | unshare/setns (namespace creation) | mitigate | Blocked by seccomp profile + --cap-drop ALL |
| T-02-15 | E (Elevation) | clone with namespace flags | mitigate | Seccomp rule blocks clone when CLONE_NEWUSER|CLONE_NEWNS|CLONE_NEWPID|CLONE_NEWNET|CLONE_NEWIPC|CLONE_NEWUTS flags are set (value=2080505856). Unmasked clone for threads is allowed. |
