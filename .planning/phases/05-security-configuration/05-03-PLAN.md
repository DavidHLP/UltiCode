    **Part A: Verify CONF-01 (JWT Cookie Secure flag) -- NO CHANGES NEEDED**

    The research confirms:
    - `application.yml` sets `jwt.cookie.access-token.secure: ${JWT_COOKIE_SECURE:false}` and same for refresh-token
    - `application-prod.yml` overrides both to `secure: true`
    - `JwtProperties.java` has `boolean secure = true` default with setter
    - `AuthServiceImpl.java` and `OAuthService.java` both use `config.isSecure()` when building Set-Cookie headers

    Verify by reading the three files listed above and confirming these facts.

    **Part B: Implement CONF-02 (actuator endpoint restriction)**

    Add the following `management:` section to `application-prod.yml`. Place it after the `cors:` section (added by Plan 05-01) and before the `logging:` section:

    ```yaml
    # Actuator - restrict endpoints in production
    management:
      endpoints:
        web:
          exposure:
            include: health
      endpoint:
        health:
          show-details: never
          show-components: never
    ```

    This ensures:
    - Only `/actuator/health` is accessible (all other actuator endpoints return 404)
    - Health endpoint does not show disk space, database connectivity, or other details
    - Endpoints like `/actuator/env`, `/actuator/beans`, `/actuator/configprops`, `/actuator/mappings` are inaccessible
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public internet -> /actuator/* | Untrusted users must not access sensitive operational endpoints |
| Production environment -> JWT cookies | Cookies must only transmit over HTTPS |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-03-01 | I (Information Disclosure) | /actuator/env exposes secrets | mitigate | production profile sets `management.endpoints.web.exposure.include: health` -- only health endpoint exposed |
| T-05-03-02 | I (Information Disclosure) | /actuator/health shows DB/Redis details | mitigate | production profile sets `management.endpoint.health.show-details: never` and `show-components: never` |
| T-05-03-03 | S (Spoofing) | JWT cookie sent over HTTP | mitigate | production profile sets `jwt.cookie.*.secure: true` -- cookies only sent over HTTPS |
| T-05-03-04 | I (Information Disclosure) | Swagger UI exposes API structure | mitigate | production profile sets `springdoc.swagger-ui.enabled: false` and `springdoc.api-docs.enabled: false` |
</threat_model>
