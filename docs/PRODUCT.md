# 产品与领域

本文是 UltiCode 当前产品定位、用户角色、核心能力和领域边界的主题入口。实现、配置、契约和测试仍是行为真相；完整稳定术语表保留在根目录 [`CONTEXT.md`](../CONTEXT.md)。

## 产品定位

UltiCode 是一个可自托管的在线评测平台，提供题目、比赛、提交评测、用户互动和管理能力。仓库交付的是代码、配置、脚本和可复现的本地/容器验证路径；仓库本身不声称拥有生产环境、真实流量或外部凭据。

## 当前用户角色

- **普通用户**：注册/登录、浏览题目和比赛、提交代码、查看评测结果，并使用平台提供的社区或通知功能。
- **管理者**：通过 Management 端执行题目、比赛、用户、审核、提交管理和运营查询；权限受 Auth 身份与 Admin/Moderation 策略约束。
- **评测与运行操作者**：启动本地或受控环境，管理 Owner 数据、Judge/Search worker、迁移、备份和恢复；其操作必须遵循 [`OPERATIONS.md`](OPERATIONS.md) 与 Services runbook。
- **贡献者与自动化代理**：遵循 [`AGENTS.md`](../AGENTS.md)，先从 [`index.md`](index.md) 找到当前权威主题，再回到代码、配置和测试。

## 当前能力边界

### 用户与身份

Auth 负责账号、凭据、会话、OAuth/JWT/JWKS、权限和身份查询；浏览器 Cookie、CSRF、refresh rotation、WebSocket 身份和权限边界见 [`REFERENCE.md`](REFERENCE.md) 与 [`ARCHITECTURE.md`](ARCHITECTURE.md#安全架构与信任边界)。

### 受控外观设置

Console、Management 与独立 Landing 共享 shadcn-vue 组件和语义主题。用户可调整主题色、基础色、图表配色、字体、圆角、密度、菜单样式及明暗模式；组件风格固定为已集成的 Nova，通用图标固定为 Lucide，不提供尚未接入的风格或图标选项。

设置支持实时预览、应用、取消和恢复默认，无需运行 CLI 或重新构建。偏好按访客或登录用户分区保存在当前浏览器；刷新和同源页面、标签页之间保持一致，不承诺跨设备或跨域同步。取消恢复已保存设置；存储失败明确提示，不把临时内存状态当作保存成功。外观设置不开放任意 CSS、HTML、脚本或布局编辑，不改变认证、权限、业务状态与专业编辑器的高对比度模式。

### 题目、比赛与社区

App 负责用户侧题目、比赛、内容、社区、资料和搜索读取等业务边界。题目与比赛的具体字段、状态和管理入口以 App owner 实现、API contract 和共享类型为准；不要仅根据本页概括扩展 wire contract。

### 提交与评测

Submission 负责提交 intake、生命周期、generation/fence、verdict/result 和 rejudge 管理；Judge worker 消费受控队列并执行评测路径。提交状态的跨 Owner 读模型、队列、outbox/inbox 和失败语义见 [`ARCHITECTURE.md`](ARCHITECTURE.md#数据流契约与事务) 与 [`REFERENCE.md`](REFERENCE.md)。

### 通知与搜索

Notification 负责通知意图、Inbox、delivery ledger、重试和管理契约；Search worker 维护派生索引，App 在索引不可用时遵循已有的降级读取边界。Search 不是 Owner 业务数据的备份，也不是新的事实来源。

### 管理与运营

Admin 负责管理、审核、审计、设置、监控、备份编排和运营查询；具体权限、审批和恢复边界由 Auth、Admin 与 [`SERVICES_ISSUES.md`](../services/docs/SERVICES_ISSUES.md) 共同约束。

### 提交复盘与学习计划

Agent 提供独立的多轮分析工作区 `/agent`，首版仅支持本人普通练习提交。用户从提交详情进入后，会话固定绑定该提交；侧栏可恢复历史会话，后续问题继续使用同一对象与有界的前文上下文。`/personal/agent` 保留为旧学习计划线程链接的迁移入口，不替代新工作区。提交详情仍保留单次复盘与可选学习计划流程；新建对话不会复用或更改该工作流状态。工作区由 `VITE_AGENT_REVIEW_ENABLED=true` 显式启用，默认关闭；关闭或 Agent 不可用不改变题目、判题、源码查看与原题解流程。

这套整合沿用 [Notion 产品定义与交互契约](https://app.notion.com/p/3f374b09d6af81dca56fda4e4c1aaa35)、[DAV-54](https://linear.app/davidhlp/issue/DAV-54)、[DAV-56](https://linear.app/davidhlp/issue/DAV-56) 的“本人普通练习提交详情”主入口决定，复用 [GitHub #287](https://github.com/DavidHLP/UltiCode/pull/287) 的工作流交互和 [#288](https://github.com/DavidHLP/UltiCode/pull/288) 的受控本地分析边界。外部记录中的设计完成、历史测试及旧执行队列退役不代表当前版本已完成真实用户试点或正式模型/Java 验收；运行事实仍以当前代码、授权和当次验证为准。

能力按用户任务组织，而不是按 Agent 内部技术划分页面：

| 用户任务 | 业务内交互 | 保留的边界 |
| --- | --- | --- |
| 理解某次提交 | 从本人提交详情打开 Agent 工作区；失败和通过提交可预填对应问题；用户发送后才创建并运行对话 | 只接收本人、明确普通练习、已知终态；未知资格、比赛和判题中不开放；每个会话固定绑定一个提交 |
| 获取结论和下一步 | 独立工作区按轮次显示问题、回答、运行状态和后续追问 | 新会话与既有单次复盘工作流分离；分析期间允许取消当前轮 |
| 核对分析依据 | 按需展开事实、假设、来源引用和工具活动 | 引用来自服务端核验；不把合成语料当作真实提交源码；对话记录不包含提交源码摘录 |
| 保存学习计划 | 在提交详情的单次复盘面板中可选编辑草稿，再分别确认和保存 | 确认绑定当前版本与摘要；编辑后需重新确认；删除对话不影响已保存计划 |
| 找回与核对结果 | 从工作区历史会话恢复对话；旧线程链接仍由 `/personal/agent` 迁移 | 会话归属与提交必须匹配；删除会话仅删除对话轮次，不删除单独保存的学习计划 |
| 暂停与返回练习 | 导航离开会话后可从历史恢复；可取消当前分析轮 | 取消只影响当前轮，不删除历史；已保存对话保留至用户主动删除 |

数据范围在发送时说明：常规模式使用经授权的提交元数据与资料；已有本地 `owner_source` 手动模式要求每轮单独确认源码外发。前端不上传编辑器内容、测试数据或用户凭据，也不自行开放新的源码能力。源码仅按现有后端限制在请求期使用，不写入对话、事件或检查点。

可用性来自认证的 `/agent/capabilities`，工作区显示能力加载状态和失败反馈；每个操作仍由服务端重新检查所有权、提交资格和运行授权。会话与每轮问题/回答保存在 Agent 私有 SQLite 中，直到用户删除；删除仅清除对话数据，已保存学习计划仍由 App Java 独立管理。工作区会话列表与 `/agent/threads` 学习计划工作流相互独立。非 loopback 实时分析需要已配置的有效预算策略、活动周期和共享账本守卫；持久化学习计划仍需明确部署启用并由用户分别确认和保存。前端开关不是授权；保存相关能力不能从 `awaiting_confirmation` 状态推断。取消只作用于当前轮；旧运行事件不能覆盖新上下文。工作区复用现有主题、双语文案和 UI 组件，桌面采用历史侧栏与对话主区，窄屏把历史收纳为抽屉。

当前 Agent 前端优化阶段仅覆盖桌面端布局、交互与验收；暂不进行移动端修复或移动端测试。现有窄屏适配保留，但不代表已完成移动端验收；移动端问题与验证留待后续明确恢复该范围后处理。

桌面端会话侧栏可收起，底部提供题库和本人提交记录入口；没有历史记录时隐藏搜索框。首次对话的输入区紧邻引导内容，进入会话后固定在消息区下方。删除会话使用确认对话框说明保留规则，工具活动按需展开；交互控件复用共享 shadcn-vue 组件。 页头把刷新和删除收纳到会话操作菜单，提交编号简写并可悬停查看完整值。历史失败轮次默认收起，展开后展示可理解的失败原因；当前失败轮次默认展开，区分源码保护、证据核验、资料不可用及响应格式问题，已有成功回答继续保留。 侧栏边缘使用共享 shadcn-vue Resizable 分隔条，可拖动或用左右方向键调整宽度，并限制调整范围以保留正文空间；同页收起再展开保留调整后的宽度。 消息、输入区、资料引用和工具活动按官方 shadcn-vue AI Elements 的 Message/Bubble、Input Group、Sources/Tool（Trace）组合实现，基础组件统一由共享 design-system 提供。回答仍通过现有 Markdown 清洗流程；工具活动仅显示已有安全事件与状态，不展示模型私有推理、源码正文或未经提供的工具输出。

消息提供复制回答和复用提问操作；复用会恢复该轮参考资料并清除源码授权，已有草稿或分析运行中不能复用。最新回答下方的后续建议只填写草稿，不自动发送。引用编号使用官方 Inline Citation 的 HoverCard 组合预览已核验的说明、来源与位置，不展示源码摘录。输入区的资料总览展示当前题目、绑定提交、题目说明与两类评论数量，并可进入选择器修改；源码授权使用官方 Confirmation 的 Item 组合，单独标识下一次发送是否已授权，变更参考资料后需要重新授权。运行与排队状态复用 Trace，展示实际状态并保留取消入口；没有完整 token 窗口数据时不显示推测的 Context 用量。

“选择上下文”允许搜索题目、分页选择本人普通练习提交，并可附上对应题目说明、同题题解评论，以及有权查看的论坛评论与回复。论坛按帖子分页选择，并可筛选本页标题；论坛参考与同题评论分开标识。更换提交会开始新分析，旧会话保持原绑定。每轮两类评论合计最多三条，每条不超过 2,000 字；题目说明最多发送 8,000 字并标记截断。发送前展示所选参考资料及外部模型用途，源码同意保持独立。服务端只持久化引用选择，运行时重新读取并校验题解所属题目、帖子访问权限和评论存在性；评论作为不可信参考文本，不作为源码、可信结论或已核验引用。

会话时间按服务端 Unix 秒时间戳或 ISO 时间字符串显示，并标明本地时区。请求异常后读回已确认的终态时，以保存状态为准，不再误报连接失败；模型响应格式错误单独说明，重试仍由用户明确触发，不自动重新请求模型。

工作区支持按标题和最后问题筛选已加载的历史记录；这不是服务端全历史搜索。桌面历史以单行标题呈现，悬停或键盘聚焦可查看最后问题、时间和轮次；搜索可一键清空或按 Esc 清空并保留输入焦点。侧栏开关位于侧栏页头，收起后在正文页头提供展开入口，切换时保留草稿、宽度及开关焦点。桌面授权区保留完整的逐次源码外发说明，省去重复的模式文案和卡片标题；输入框从单行高度随内容增长，上限后在框内滚动。绑定提交后的建议问题只填入输入框，不会自动发送。Enter 发送、Shift + Enter 换行，输入法组合期间不会发送；阅读旧消息时暂停自动跟随，可点击回到最新消息。引用来源按需展开。

主动发送或重试会恢复跟随最新轮次；消息更新时保留更新前的跟随意图，避免布局变化被误判为用户主动回看。取消会立即保留取消终态，已发给模型的请求仍可能完成并产生用量，但后续分析与回答保存会被取消栅栏阻止。

首版不新增学习计划列表、跨用户分享、团队协作、全历史搜索、标签、全局悬浮聊天、管理后台、用户画像或统计埋点。已保存对话可从历史列表恢复；会话仅对所属用户开放。保存不等于学习有效，点击与生成不等于需求得到验证；真实用户研究、模型质量和实际业务链路验证须分别说明环境与证据，不由 UI 或离线测试代替。历史 U02/U03/U04 验收驱动已退役，不再作为产品能力开关。

## 领域对象与术语

稳定术语以 [`CONTEXT.md`](../CONTEXT.md) 为准；当前主题中常见的边界对象包括：

- **Account / User / principal**：Auth 的身份、账号状态和认证主体。
- **Problem / Contest**：App 的题目与比赛聚合及其管理数据。
- **Submission / generation / attempt**：Submission 的提交生命周期和并发/重试隔离单位。
- **Verdict / result / fence**：评测结果及防止旧结果覆盖新状态的边界。
- **Owner / Worker**：拥有业务数据与写入权的服务，或处理派生/队列工作的独立 worker。
- **Contract / command / event / receipt**：跨 Owner 的接口、命令、事件和幂等回执；契约细节见 [`REFERENCE.md`](REFERENCE.md)。

本页只说明概念归属，不复制每个 DTO、数据库列或状态机；需要精确字段时应读取实现和 contract module。

## 拓扑与明确边界

当前默认拓扑是 distributed：五个 Data Owner（Auth、Admin、App、Submission、Notification）与两个 Worker（Judge、Search）各自保留边界。Core profile 是受限的可选验证 testbed，不是默认产品拓扑；其有效性还受本地输入和现有 issue gate 约束。

平台基础设施（MySQL、Redis、Nacos、MeiliSearch、SMTP、对象存储等）是运行依赖，不等于新的业务 Owner。共享基础设施的故障域、权限和恢复证据见 [`OPERATIONS.md`](OPERATIONS.md) 及 Services runbook。

仓库不承诺生产 active-active HA、透明故障转移、生产 RPO/RTO 或外部部署结果。Kubernetes、Kafka、Service Mesh 等未纳入当前产品能力；如需评估，先以源码、配置、门禁和 Services issue registry 为准。
