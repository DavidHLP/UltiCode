# UltiCode 项目总纲

> 基于 Dubbo3 + Spark 的分布式编程题目推荐系统

## 一、项目概述

### 1.1 项目背景

UltiCode 是一个面向编程竞赛选手的在线编程训练平台，类似于 LeetCode。本项目为该总平台的**推荐模块**，采用 Dubbo3 分布式微服务架构，基于 Spark 进行大规模数据处理和机器学习推荐。

### 1.2 项目定位

- **项目性质**：本科毕业设计
- **核心功能**：为用户提供个性化的编程题目推荐
- **技术特色**：分布式微服务架构 + 大数据推荐算法

### 1.3 项目目标

1. 构建高性能、可扩展的分布式推荐服务
2. 实现多策略融合的智能推荐算法
3. 支持实时推荐与离线批处理相结合

## 三、数据模型

### 3.1 核心数据实体

基于现有数据库分析，推荐模块需要依赖以下核心数据：

#### 用户数据 (users)
| 字段 | 类型 | 说明 |
|------|------|------|
| id | varchar(40) | 用户ID |
| username | varchar(120) | 用户名 |
| rating | int | 竞赛积分 |
| preferred_language | varchar(50) | 偏好编程语言 |
| role | enum | 用户角色 |

#### 题目数据 (problems)
| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 题目ID |
| slug | varchar(120) | 题目标识 |
| title | varchar(255) | 题目标题 |
| difficulty | enum | 难度 (Easy/Medium/Hard) |
| acceptance_rate | decimal | 通过率 |

#### 题目标签 (problem_tags)
| 字段 | 类型 | 说明 |
|------|------|------|
| id | varchar(40) | 标签ID |
| label | varchar(120) | 标签名称 |
| slug | varchar(120) | 标签标识 |

**现有标签包括**：Array, String, Hash Table, Sliding Window, Sorting, Dynamic Programming, Tree, Graph 等 30+ 个算法标签

#### 提交记录 (submissions)
| 字段 | 类型 | 说明 |
|------|------|------|
| id | varchar(40) | 提交ID |
| user_id | varchar(40) | 用户ID |
| problem_id | bigint | 题目ID |
| language | varchar(20) | 编程语言 |
| status | enum | 提交状态 |
| runtime | int | 运行时间(ms) |
| memory | int | 内存使用(KB) |

#### 全球排名 (global_rankings)
| 字段 | 类型 | 说明 |
|------|------|------|
| user_id | varchar(40) | 用户ID |
| rating | int | 当前积分 |
| max_rating | int | 历史最高积分 |
| rating_title | enum | 段位称号 |

**段位等级**：NEWBIE → PUPIL → SPECIALIST → EXPERT → CANDIDATE_MASTER → MASTER → INTERNATIONAL_MASTER → GRANDMASTER → INTERNATIONAL_GRANDMASTER → LEGENDARY_GRANDMASTER

### 3.2 推荐系统数据模型

推荐模块需要新增以下数据结构：

```
用户特征向量 (user_features)
├── 能力特征：各难度题目的通过率、平均用时
├── 偏好特征：偏好的标签、编程语言
├── 行为特征：活跃时段、提交频率
└── 历史特征：历史做题记录、错题本

题目特征向量 (problem_features)
├── 难度特征：难度等级、通过率
├── 标签特征：所属标签向量
├── 质量特征：点赞数、收藏数
└── 相似题特征：相似题目列表

推荐结果 (recommendations)
├── 用户ID
├── 题目ID列表
├── 推荐分数
├── 推荐理由
└── 生成时间
```

└─────────────────────────────────────────────────────────────┘

### 4.2 推荐场景

| 场景 | 策略 | 说明 |
|------|------|------|
| **每日推荐** | 协同过滤 + 内容推荐 | 基于用户能力推荐适合的题目 |
| **相似题目** | 内容相似度 | 做完一题后推荐相似题目 |
| **薄弱点突破** | 错题分析 | 针对薄弱标签推荐练习 |
| **进阶挑战** | 能力评估 | 推荐略高于当前能力的题目 |
| **竞赛准备** | 知识图谱 | 按竞赛知识点系统推荐 |

### 4.3 特征工程

```
用户特征：
├── 静态特征
│   ├── 注册时长
│   ├── 历史最高积分
│   └── 偏好语言
├── 动态特征
│   ├── 近7天提交数
│   ├── 各难度通过率
│   └── 各标签掌握度
└── 行为特征
    ├── 平均做题时长
    ├── 错题重试率
    └── 收藏/点赞行为

题目特征：
├── 基础特征
│   ├── 难度等级
│   ├── 标签向量
│   └── 通过率
├── 质量特征
│   ├── 题解数量
│   ├── 点赞数
│   └── 收藏数
└── 关联特征
    ├── 前置题目
    ├── 相似题目
    └── 竞赛来源
```

## 六、性能优化

### 6.1 缓存策略

为实现推荐响应时间 < 200ms 的目标，系统采用多级缓存架构：

#### Provider 服务层缓存 (Caffeine)
- **位置**: `recommend-provider` 模块
- **实现**: Spring Cache + Caffeine
- **配置**:
  - 最大缓存条目: 1000
  - TTL (Time-To-Live): 5分钟
  - 缓存键: `userId_scenario_size`
- **作用**: 缓存推荐结果，避免重复计算

```yaml
spring:
  cache:
    type: caffeine
    caffeine:
      spec: maximumSize=1000,expireAfterWrite=5m
```

#### FeatureStore 特征缓存
- **位置**: `recommend-feature` 模块
- **实现**: ConcurrentHashMap + TTL包装
- **配置**:
  - 默认 TTL: 5分钟 (300,000ms)
  - 支持自定义 TTL
- **特性**:
  - 读写时自动清理过期条目
  - 统计命中率
  - 批量操作支持

### 6.2 性能指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| P50 响应时间 | < 100ms | 50%请求的响应时间 |
| P99 响应时间 | < 200ms | 99%请求的响应时间 |
| 缓存命中率 | > 80% | 热点数据命中率 |
| 吞吐量 | > 1000 QPS | 单实例吞吐量 |

### 6.3 性能优化建议

1. **生产环境**: 考虑使用 Redis 替代 Caffeine 实现分布式缓存
2. **监控**: 启用 Caffeine 统计功能监控缓存效率
3. **预热**: 系统启动时预加载热点用户特征
4. **异步更新**: 对于非实时要求的特征，使用异步更新策略
