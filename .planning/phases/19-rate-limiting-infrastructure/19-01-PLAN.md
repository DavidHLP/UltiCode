## Current Behavior (Gap)
`GlobalExceptionHandler.handleBusinessException()` at lines 35-42 returns 429 status for rate limit errors but does NOT include a `Retry-After` header. The `RateLimitAspect` (lines 52-56) already extracts TTL from Redis and passes it in the exception message:

```java
Long ttl = redisTemplate.getExpire(redisKey, TimeUnit.SECONDS);
throw new BusinessException(ErrorCode.TOO_MANY_REQUESTS,
    "Rate limit exceeded. Please try again in " + (ttl != null ? ttl : rateLimit.period()) + " seconds.");
```

The TTL value is available in the exception message but not extracted for the HTTP header.

## Required Fix
Modify `handleBusinessException()` to detect when `HttpStatus.TOO_MANY_REQUESTS` is thrown (via `ex.getHttpStatus() == HttpStatus.TOO_MANY_REQUESTS`) and extract the retry seconds from the exception message via regex, then add it as a `Retry-After` header.

    log.warn("Business exception: code={}, message={}, traceId={}",
            ex.getCode(), ex.getMessage(), ex.getTraceId());

    Result<Void> result = Result.error(ex.getCode(), ex.getMessage(), ex.getTraceId());

Replace with:
```java
@ExceptionHandler(BusinessException.class)
public ResponseEntity<Result<Void>> handleBusinessException(BusinessException ex) {
    log.warn("Business exception: code={}, message={}, traceId={}",
            ex.getCode(), ex.getMessage(), ex.getTraceId());

    Result<Void> result = Result.error(ex.getCode(), ex.getMessage(), ex.getTraceId());

    HttpStatus status = ex.getHttpStatus();
    ResponseEntity.BodyBuilder responseBuilder = ResponseEntity.status(status);

    // Add Retry-After header for rate limit responses
    if (ex.getHttpStatus() == HttpStatus.TOO_MANY_REQUESTS) {
        String message = ex.getMessage();
        java.util.regex.Matcher matcher = java.util.regex.Pattern.compile("(\d+) seconds?").matcher(message);
        if (matcher.find()) {
            responseBuilder.header(HttpHeaders.RETRY_AFTER, matcher.group(1));
        }
    }

    return responseBuilder.body(result);
}
```
