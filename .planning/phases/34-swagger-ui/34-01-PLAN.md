## Phase 34 Plan 01: 启用 Swagger UI

### Objective

启用 springdoc Swagger UI，使 `/swagger-ui.html` 正常访问。

### Tasks

#### T-01: 启用 SwaggerConfig.java

<read_first>
backend-spring/src/main/java/com/ulticode/common/config/SwaggerConfig.java
</read_first>

<acceptance_criteria>
- grep -q "@Configuration" backend-spring/src/main/java/com/ulticode/common/config/SwaggerConfig.java
- grep -q "public OpenAPI openAPI()" backend-spring/src/main/java/com/ulticode/common/config/SwaggerConfig.java
- grep -q "@Bean" backend-spring/src/main/java/com/ulticode/common/config/SwaggerConfig.java
</acceptance_criteria>

<action>
取消 SwaggerConfig.java 的注释：
1. 移除行1-2的 `package` 之前的多行注释 `// TEMPORARILY DISABLED...`
2. 取消第5行的 `@Configuration` 注释
3. 取消第7-27行的 `@Bean` 方法注释
4. 保留原有的 `OpenAPI` 配置（title, description, version, contact, license, security）
</action>

#### T-02: 启用 springdoc 配置

<read_first>
backend-spring/src/main/resources/application.yml
</read_first>

<acceptance_criteria>
- grep -q "enabled.*true" backend-spring/src/main/resources/application.yml
- 不应再有 "enabled.*false" 在 springdoc 块中
</acceptance_criteria>

<action>
在 application.yml 中修改 springdoc 配置：
- 将 `springdoc.swagger-ui.enabled: false` 改为 `true`
- 将 `springdoc.api-docs.enabled: false` 改为 `true`
环境变量 `SPRINGDOC_ENABLED` 可覆盖此设置
</action>

#### T-03: 验证 Swagger UI

<acceptance_criteria>
- Backend 启动后 `curl -s -o /dev/null -w "%{http_code}" http://localhost:9001/swagger-ui.html` 返回 200
- `curl -s http://localhost:9001/v3/api-docs` 返回有效的 OpenAPI JSON
</acceptance_criteria>

<action>
验证步骤（在本地启动 backend 后执行）：
1. `curl -s -o /dev/null -w "%{http_code}" http://localhost:9001/swagger-ui.html` 应返回 200
2. `curl -s http://localhost:9001/v3/api-docs | head -20` 应返回 OpenAPI JSON
</action>

### Verification

must_haves:
1. Swagger UI 页面加载返回 HTTP 200
2. API 文档显示所有 REST endpoints（访问 /swagger-ui.html 验证）
3. Try-out 功能可正常发送请求（在浏览器中测试）

### Notes

- springdoc 2.6.0 已确认与 Spring Boot 3.2.x 兼容
- SecurityConfig.java 中 PUBLIC_ENDPOINTS 已包含 Swagger 路径，无需修改安全配置
- 依赖已在 pom.xml 中声明，无需添加新依赖
