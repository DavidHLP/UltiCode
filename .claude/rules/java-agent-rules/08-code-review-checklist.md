# Java Code Review Agent Checklist

## 审查顺序

1. **编译与运行风险**：空指针、数组越界、集合并发修改、浮点精度、包装类型比较、过时 API。
2. **并发与资源风险**：线程池创建方式、ThreadLocal 回收、锁释放、死锁顺序、定时任务异常隔离。
3. **异常与日志**：异常是否被吞、日志是否包含必要上下文、是否重复打印堆栈、是否泄露敏感信息。
4. **数据库风险**：索引命中、SQL 可维护性、分页/排序、ORM 字段映射、事务边界、慢 SQL 隐患。
5. **安全风险**：鉴权、越权、输入校验、SQL 注入、敏感数据输出、外部接口参数保护。
6. **可维护性**：命名、方法长度、注释同步、分层边界、接口兼容、魔法值、重复逻辑。
7. **测试保障**：正常路径、异常路径、边界值、并发场景、数据库变更和回归用例。

## 输出格式建议

Code Review 时按以下格式输出：

```md
## 结论
- 是否通过：是/否
- 风险等级：高/中/低

## 必须修复
1. [文件:行号] 问题：...
   - 原因：...
   - 建议：...

## 建议优化
1. ...

## 已符合规范
- ...
```

## 最小修复原则

- 优先修复【强制】项。
- 不为了格式重构破坏业务逻辑。
- 不引入与项目技术栈不一致的新依赖。
- 涉及公共接口签名、数据库结构、权限逻辑时，必须提示兼容性和回归测试影响。
