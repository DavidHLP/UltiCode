    Create AuthControllerTest.java per D-08, D-09, D-10. This is a NEW pattern in the codebase (RESEARCH: zero existing @WebMvcTest tests). The key challenge is handling SecurityConfig dependencies (RESEARCH Pitfall 2).

    **Class structure:**
    ```java
    @WebMvcTest(AuthController.class)
    @DisplayName("AuthController")
    class AuthControllerTest {

        @Autowired
        private MockMvc mockMvc;

        // Service dependencies (what AuthController actually uses)
        @MockBean private AuthService authService;
        @MockBean private CsrfService csrfService;
        @MockBean private UserService userService;
        @MockBean private PasswordResetService passwordResetService;
        @MockBean private OAuthService oauthService;
        @MockBean private PermissionService permissionService;

        // SecurityConfig dependencies that @WebMvcTest tries to load
        @MockBean private JwtTokenProvider jwtTokenProvider;
        @MockBean private JwtProperties jwtProperties;
        @MockBean private AuthenticationEntryPointImpl authenticationEntryPoint;
        @MockBean private CorsProperties corsProperties;
        @MockBean private StringRedisTemplate stringRedisTemplate;
    }
    ```

    NOTE: Do NOT @MockBean CsrfValidationFilter -- it is NOT a @Component (RESEARCH Pitfall 3). It is instantiated inline in SecurityConfig.

    **Test cases (per D-10):**

    1. **login_success:** Mock authService.login(any(), any()) to return LoginResponse with csrfToken and UserVO. POST JSON {"username":"testuser","password":"password123"}. Assert status().isOk(), jsonPath("$.code").value(0), jsonPath("$.data.csrfToken").exists(), jsonPath("$.data.user.username").value("testuser").

    2. **login_validationError_blankUsername:** POST {"username":"","password":"pass"}. Assert status().isBadRequest() (LoginDTO has @NotBlank on username).

    3. **login_unauthorized_badCredentials:** Mock authService.login to throw BusinessException(ErrorCode.AUTH_INVALID_CREDENTIALS). POST valid JSON. Assert appropriate error response.

    4. **getCurrentUser_success:** Use `.with(user("user-1"))` to provide Principal. Mock userService.findById("user-1") to return Optional.of(user). Mock userService.toVO(user) to return UserVO. Mock csrfService.generateToken("user-1") to return "csrf-token". GET /auth/me. Assert $.code=0, $.data.user.id="user-1", $.data.csrfToken="csrf-token".

    5. **getCurrentUser_unauthorized:** GET /auth/me without .with(user(...)). Assert status().isUnauthorized() or isForbidden().

    6. **logout_success:** POST /auth/logout. Mock authService.logout(any()). Assert status().isOk(), $.code=0.

    **Important implementation notes:**
    - LoginResponse is a class with fields csrfToken and user (UserVO). Build it with setters or builder.
    - UserVO needs at minimum id and username fields set.
    - LoginDTO has @NotBlank on username and @NotBlank on password fields.
    - Use `import static org.springframework.test.web.servlet.request.MockMvcRequestBuilders.*`
    - Use `import static org.mockito.ArgumentMatchers.*` and `import static org.mockito.Mockito.when`
    - Use `ObjectMapper` to serialize request bodies, or use raw JSON strings in `.content()`
    - If @WebMvcTest fails to load context due to missing beans, add more @MockBean fields. The RESEARCH identifies all required beans but Spring may scan additional ones.

    **Troubleshooting fallback (from RESEARCH Open Question 2):**
    If @MockBean approach fails with UnsatisfiedDependencyException, add:
    `@WebMvcTest(value = AuthController.class, excludeAutoConfiguration = SecurityAutoConfiguration.class)`
    This disables security filters entirely, but then /auth/me tests need adjustment (no Principal injection).
    Prefer the @MockBean approach first.
