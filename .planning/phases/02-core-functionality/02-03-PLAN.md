1. Create `docker/sandbox/seccomp-profile.json` with this exact content. This is an ADDITIVE profile on top of Docker's default seccomp (D-15). It only specifies additional syscalls to block -- Docker's default allowlist for common runtime operations (futex, mmap, clone for threads, etc.) remains active.

```json
{
    "defaultAction": "SCMP_ACT_ALLOW",
    "architectures": [
        "SCMP_ARCH_X86_64",
        "SCMP_ARCH_X86",
        "SCMP_ARCH_AARCH64"
    ],
    "syscalls": [
        {
            "names": ["ptrace", "mount", "keyctl", "unshare", "setns"],
            "action": "SCMP_ACT_ERRNO",
            "args": [],
            "comment": "Block dangerous syscalls for code execution sandbox (D-08)"
        },
        {
            "names": ["clone"],
            "action": "SCMP_ACT_ERRNO",
            "args": [
                {
                    "index": 0,
                    "op": "SCMP_CMP_MASKED_EQ",
                    "value": 2080505856
                }
            ],
            "comment": "Block clone with namespace flags (CLONE_NEWUSER|CLONE_NEWNS|CLONE_NEWPID|CLONE_NEWNET|CLONE_NEWIPC|CLONE_NEWUTS) only -- standard thread creation via clone is allowed"
        }
    ]
}
```

CRITICAL: `defaultAction` is `SCMP_ACT_ALLOW` (not `SCMP_ACT_ERRNO`). This means all syscalls are allowed EXCEPT the ones explicitly listed. This is the safe incremental approach (D-15) that won't break language runtimes. The clone rule uses `SCMP_CMP_MASKED_EQ` with value `0x7C020000` (2080505856 decimal) to match only when namespace creation flags are present, allowing normal thread creation used by Java, Node.js, and Python.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User code -> Container runtime | Untrusted code executing inside Docker sandbox |
| Container -> Linux kernel | Syscall interface (seccomp enforcement point) |
| Container -> Docker daemon | Capability interface (cap-drop enforcement point) |
| Container -> Network | Blocked entirely (--network none) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-11 | Elevation of Privilege | sandbox | mitigate | --cap-drop ALL removes all Linux capabilities (D-09). No CAP_SYS_ADMIN, CAP_SYS_PTRACE, etc. |
| T-02-12 | Elevation of Privilege | sandbox | mitigate | Custom seccomp profile blocks ptrace, mount, keyctl, unshare, setns (D-08). clone blocked only with namespace flags |
| T-02-13 | Elevation of Privilege | sandbox | mitigate | --security-opt no-new-privileges:true prevents setuid/setgid escalation |
| T-02-14 | Denial of Service | sandbox | mitigate | Resource limits: --memory 256m, --cpus 1.0, --pids-limit 128, --ulimit nofile=128:128 |
| T-02-15 | Elevation of Privilege | sandbox | mitigate | --network none prevents exfiltration and C2 communication (D-10, already present) |
| T-02-16 | Tampering | sandbox | mitigate | --read-only filesystem prevents persistent modification. --tmpfs for /tmp only (64m) |
| T-02-17 | Elevation of Privilege | clone syscall | mitigate | Conditional block only on namespace flags (0x7C020000). Normal thread creation for Java/Node/Python is unaffected |
| T-02-18 | Elevation of Privilege | seccomp profile | accept | Profile uses SCMP_ACT_ALLOW as default -- allows all syscalls except explicitly blocked ones. Defense-in-depth, not sole boundary |
</threat_model>
